# RiskLens 第三方复核协议 v1

本协议用于高校法学院、律师事务所、司法科技研究团队或独立评测机构复核 RiskLens。
签署方不是为产品背书，而是确认评测过程、数据来源和报告是否可复现。

## 复核方最低条件

- 与项目开发团队不存在影响独立判断的直接利益关系；
- 能说明机构名称、复核人员角色及利益冲突情况；
- 至少一名成员具备法律研究、司法实务或法律科技评测经验；
- 能独立取得密封测试集并保存其 SHA-256；
- 不接受开发团队挑选或删除失败案例。

仅使用第三方 AI 模型不等于“第三方机构认证”。AI 裁判属于评测工具，机构复核属于程序性见证，
两者必须在比赛材料中明确区分。

## 复核步骤

1. 从法院官方来源抽样核对案例事实、裁判结果、争议焦点和法律依据。
2. 运行 `python -m backend.evals.eval_cli validate`，记录数据集 SHA-256。
3. 运行 `verify-sources`，保存每个法院页面的 HTTP 状态与内容哈希。
4. 确认测试输入不含案号、当事人姓名和可直接定位原裁判的独特标识。
5. 在开发团队无法修改的环境中运行 RiskLens，保存原始请求与响应哈希。
6. 使用至少两个不同身份的裁判模型评分，并披露模型、提供方、提示词哈希和温度。
7. 对裁判分差超过 0.20 的案例进行第三次复核；不得以平均分掩盖争议。
8. 随机人工复核不少于测试集的 20%，计算人工与 AI 裁判的一致性。
9. 报告所有失败、超时、拒答和无效输出；不能只选择成功案例。
10. 使用 CLI 生成最终报告，确认状态为 `COMPLETE` 后方可公布综合分。

## 建议发布指标

- 案例数、领域、法院层级和年份分布；
- Recall@1、Recall@3、Recall@5、MRR；
- 争议焦点、法律依据、裁判方向、证据支撑和完整性分数；
- 无依据陈述率、错误引用率、有效引用率；
- 双裁判平均差异、争议率和人工抽检一致性；
- 分析成功率、拒答率、P50/P95延迟和平均调用成本；
- 95%置信区间，而不只给点估计；
- 完整失败案例附录。

## 禁止性表述

在没有对应证据时，不得使用：

- “司法鉴定认证”；
- “法院认可产品”；
- “权威机构证明准确率”；
- “零幻觉”；
- “100%正确”；
- 将法院公开案例来源描述为法院对 RiskLens 的产品背书。

允许的准确表述示例：

> 本评测使用最高人民法院公开案例作为参考答案，由两个独立模型进行结构化复核，
> 并由某机构按照公开协议复核运行过程。法院案例来源不代表法院对产品作出认证或背书。
